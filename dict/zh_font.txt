# System Informer 中文 · 字体替换表
# ===========================================================================
# 干什么：钩子在**字体被创建的那一刻**把 LOGFONT 换掉 —— 换字体名、按比例换字号。
# 界面上所有文字都跟着变，不需要重编 System Informer。
#
# 为什么需要它（不是配置项能解决的事）：
#   System Informer 的界面字体有两个来源 ——
#     · 应用字体  PhCreateApplicationFont() → PhInitializeFont()
#                 → PhCreateFontHandle(L"Microsoft Sans Serif", 8, ...)
#                 那个 8 号写死在 phlib\guisup.c 的 PhInitializeFont 里。
#                 它管：页签、菜单栏文字、表头大字号、迷你信息窗、查找对话框、
#                 以及各对话框里的控件字体。
#     · 列表字体  PhCreateTreeWindowFont() 读设置项 "Font"；没设就用
#                 SPI_GETICONTITLELOGFONT。
#                 它管：进程列表、属性页里的所有表格/树。
#
#   第二条在中文 Windows 上**本来就是 Microsoft YaHei UI 9 号**（系统图标标题字体
#   就是它）—— 实测 [fontall] 里 SI 建的列表字体就是 "Microsoft YaHei UI" h=-12。
#   所以真正的缺口只有第一条那个写死的 8 号，本表只补它。
# ===========================================================================
#
# 格式：每行「原字体[|原字号]<TAB>新字体[|新字号]」，# 开头是注释。
#   · 只给字体名      只换名字，字号不动
#   · 两侧都给字号    整个字族按「新/原」等比缩放
#                     缩放的是**像素高度**，所以 DPI 缩放自动跟随 —— 不需要知道
#                     当前是多少 DPI。96 DPI 下 8 号 = 11px，乘 9/8 = 12px，正是 9 号。
#   · 没列出来的字体一律不动。**这是白名单，不是黑名单。**
#   · 新字体名必须是纯 ASCII（A 版入口 CreateFontA/CreateFontIndirectA 要把它转回
#     ANSI，非 ASCII 会让那条路静默失效，载入时判为坏行）。
#
# 三条不能碰的红线（都在钩子里硬编码了，写进来也不会生效）：
#   1. 字重 = 0（FW_DONTCARE）的跳过。
#      GDI 的字体链接在解析「MS Shell Dlg 2」和各语系替代字体时，会真的把候选字体
#      造一遍：字重 0、高度 +10，字体名横跨宋体/新宋体/Microsoft JhengHei UI/
#      Meiryo UI/Malgun Gothic/Yu Gothic UI/Arial/Segoe UI/Tahoma。换掉它们会污染
#      GDI 的字体关联表。SI 自己要用的字体永远带真实字重，所以这条判据精确且不误伤。
#   2. 字符集 = SYMBOL_CHARSET 的跳过。图标字体（Marlett 之类）的「字符」其实是
#      字形序号，换字体名等于换掉整套图标。
#   3. ★ 不要替换 Tahoma / Segoe UI 这类**系统提供的、会被标准控件拿去用**的字体。
#      这条是踩出来的：把它们也换掉之后，选项对话框里所有 Edit/Static 的拉丁字母
#      全变成鬼画符（"SystemInformer" → "Pvpbj Rkd g bo"，中文反而正常）。
#      原因是 GDI 把对话框的 "MS Shell Dlg 2" 映射成 Tahoma 去建字体，换掉它之后
#      标准控件取到的字形是错的。实测对照：
#        规则 {MS Sans Serif, Tahoma, Segoe UI} → 选项页花屏
#        规则 {MS Sans Serif}                   → 选项页正常（截图见 docs\font-compare-options.png）
#      界面由 SI 自己画的那些文字（主窗口页签/菜单/列表）不受影响，所以只看主窗口
#      是发现不了这个问题的 —— 必须开一次对话框看。
# ===========================================================================
#
# 关掉整张表：环境变量 ZHHK_FONT=0（或把本文件清空/改名）。
# 想先看看 System Informer 到底造了哪些字体（做替换前的基线）：
#   ZHHK_FONT=0  ZHHK_FONTLOG=1   然后看 zh_hook.log 里的 [fontall] 行。
# 核对 GDI 真正给了哪个字体：ZHHK_FONTFACE=1（看 [fontface] 行）。
#
# 一个已知的边界：GetStockObject(DEFAULT_GUI_FONT) 拿到的系统库存字体不是
# CreateFont 造出来的，钩不到。它只在没有应用字体时作兜底，界面里基本见不到；
# 真遇到了表现为某处文字仍是 Microsoft Sans Serif 8 号。

# 唯一的规则：SI 写死的应用字体，8 号（-11px）→ 雅黑 UI 9 号（-12px）
# [A/B 试验] Microsoft Sans Serif|8	Microsoft YaHei UI|9
# 保留原名：西文继续用 Microsoft Sans Serif（字形比雅黑拉丁更粗实），中文由 GDI 字体链接回落雅黑，与 3.2 版观感一致

# ===========================================================================
# 附：状态栏/菜单这类小字的「锯齿感」不是字体表能治的
#   症状：主窗口底部状态栏（CPU 使用率 / 物理内存 / 可用内存）中文边缘比列表区毛。
#   实测（96 DPI，截图 4× 放大对比）：
#     · 状态栏与列表是同一套字体（微软雅黑 UI 9 号 = 12px），差的不是字体而是字号档位。
#       SI 应用字体写死 8 号（phlib\guisup.c PhInitializeFont），中文在 12px 上笔画
#       只剩 1px 宽，任何抗锯齿都留不住，这是观感的根子。
#     · 真正的可调项是设置项 FontQuality（settings.json，0..6）：
#         0=DEFAULT 1=DRAFT 2=PROOF 3=NONANTIALIASED 4=ANTIALIASED
#         5=CLEARTYPE 6=CLEARTYPE_NATURAL
#       默认值是 0（DEFAULT_QUALITY），实测状态栏笔画粗、边缘带灰毛刺；
#       改成 5 后同样 4× 放大图里笔画变细、边缘是干净的子像素色彩，观感明显干净。
#       （只影响 SI 自己 CreateFont 出来的字体，也就是自绘的菜单/页签/列表/状态栏。）
#     · 想再大一号就得把应用字体整体提到 10 号（多一条
#       "Microsoft YaHei UI|9 -> Microsoft YaHei UI|10"），代价是列表行高、菜单和
#       页签一起变大，属于改版式，不是改渲染，按需再开。
# ===========================================================================

# ── 状态栏小字「锯齿 / 发虚」的真正原因（2026-11-12，读源码 + 运行期实测）──────
# 纠正上一版结论：把原因归到「字体名替换成 Microsoft YaHei UI」是错的。
# 停用替换后做逐像素差分（v40_native vs v40_nofont 状态栏区 35000 像素），
# 只有 242 个像素不同，且全部落在百分比数字上 —— 字形一个像素都没变。
# 真正原因在 SystemInformer\delayhook.c:771：
#     //SelectFont(bufferDc, GetWindowFont(WindowHandle));
# 这句被注释掉了。SI 自绘状态栏时缓冲 DC 上没选任何字体，DrawText 只能用 DC 默认的
# System 位图字体，中文靠 GDI 字体链接回落 —— 在 225% 缩放下被渲染成约 8pt 小字，
# 笔画细、边缘脏，也就是用户说的「比其它区域锯齿感重」。
# 运行期探针证实：4.0 与 3.2 的 msctls_statusbar32 窗口 DC 字体都是 face="System" lfH=16，
# 且给状态栏发 WM_SETFONT 完全无效（自绘不读控件字体）。所以换字体名 / 改 FontQuality /
# 提字号三条路都不可能有效。
# 系统显示：AppliedDPI=216（225%），物理 3840×2160，逻辑 1707×960。
# 修复（hook 层，不改 SI 源码）：HookDrawTextW / HookDrawTextExW 增加 StatusFontGet：
#   判据 = DC 当前字体解析名 == "System" 且 LOGPIXELSY > 96；
#   命中就临时 SelectObject 一个 -(9*DPI/72) 的 Microsoft YaHei UI（DEFAULT_QUALITY），画完换回。
# 实测（同窗口 800×450 DIP、同抓图方式、同裁切区、逐像素）：
#   关补丁 ZHHK_STATUSFONT=0：状态栏字面约 14px，细、发虚；
#   开补丁：字面约 26px，粗实清晰；日志 [statusfont] dcDpi=216 h=-27 face="System"。
# 参考 3.2 版：DPI-unaware，整个窗口被系统位图放大 2.25 倍，字面约 27px，糊但饱满；
# 4.0 修复后字号相当且更清晰。
# 证据图：%TEMP%\ab_status_font.png（关/开 同尺度）、%TEMP%\cmp_status_fix.png（+3.2 参考）
